3. PDF EXTRACTION FLOW
------------------------------------------------------------------------------------------------------------------------
1. Ingestion: Accepts single monthly MoSPI PAIMANA Flash Report PDF (e.g. `FlashReport_July_2026.pdf`).
2. Table Detection: Calls `detect_pdf_tables(doc, filepath)` to find the page boundaries of Table 6 ('All Ongoing Projects').
3. Layout Routing: Intelligently routes to `extract_ongoing_legacy` (Apr–Jun 2025) or `extract_ongoing_modern` (Jul 2025–Jun 2026).
4. Record Normalization: Cleans currency (Crores), dates (YYYY-MM), progress [0.00, 100.00]%, and canonical project IDs via `normalize_project_record`.
5. Deduplication: Ensures 0 duplicate `project_id` entries per extracted monthly batch.

------------------------------------------------------------------------------------------------------------------------
4. DATABASE LOOKUP FLOW
------------------------------------------------------------------------------------------------------------------------
1. Session Decoupling: Accepts SQLAlchemy `Session` / `Connection`, Pandas `DataFrame` (fixtures), or query callables.
2. Filter Scope: Queries all historical project records strictly with `report_month < as_of_month`.
3. Efficiency: Filters for `project_id = ANY(:project_ids)` when project list is provided.
4. Schema Alignment: Seamlessly joins `projects` master table and `monthly_snapshots` time-series facts.

------------------------------------------------------------------------------------------------------------------------
5. POINT-IN-TIME ENFORCEMENT (ZERO TEMPORAL LEAKAGE)
------------------------------------------------------------------------------------------------------------------------
1. Boundary Invariant: All historical lookups enforce `report_month < as_of_month`. Any rows with `report_month >= as_of_month` in the DB session are discarded before computation.
2. Dynamic Context Aggregation: State and agency statistics (mean progress, median progress, cost, expenditure ratios) are computed dynamically strictly from projects active at month $t$.
3. Forward-Fill Prohibition: Missing historical lags (e.g. for new project intakes) are preserved as `NaN` without forward-filling across prediction boundaries.
4. Target Isolation: All 4 prediction target labels (`schedule_delay_3m`, `cost_overrun_state_3m`, `schedule_revision_3m`, `cost_revision_event_3m`) and label metadata are excluded from the feature space.
