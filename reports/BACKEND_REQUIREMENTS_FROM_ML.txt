PURPOSE OF THIS DOCUMENT:
This specification establishes the authoritative, binding requirements contract for the Backend Engineering and Data
Engineering teams for SIH26103 (MoSPI / IPMD Integrated Project-Monitoring Platform). It defines the exact data structures,
two-pillar analytical architecture (Predictive Outcome Engine + Operational Execution Surveillance), 75-feature point-in-time
calculation invariants, OCMS historical data separation rules, explainability signals, prescriptive monitoring actions,
data validation rules, anomaly handling policies, and temporal safeguards necessary to power the production platform.

CORE ARCHITECTURAL PRINCIPLES FOR BACKEND:
1. TWO-PILLAR ANALYTICAL SEPARATION:
   The platform operates with two distinct, complementary analytical pillars that answer fundamentally different operational questions:
   - Pillar 1 (Predictive Outcome Engine): "What is the statistical likelihood/risk of adverse terminal delivery outcomes (delay, cost expansion, rescheduling) over the next 3 months?"
   - Pillar 2 (Operational Execution Surveillance): "Is the project exhibiting observable site-level operational friction, physical stagnation, or capital divergence right now at month t?"
   The backend must strictly maintain this separation in its database tables, API payloads, and alerting pipelines.

2. PROBABILITY VS. OPERATIONAL INDEX DISCIPLINE:
   The backend must maintain strict mathematical data type distinctions across all outputs:
   - `schedule_delay_risk`       : CALIBRATED PROBABILITY [0.0000, 1.0000] (Sigmoid/Platt calibrated Random Forest).
   - `cost_overrun_risk`         : CONTINUOUS MODEL SCORE / PROBABILITY [0.0000, 1.0000] (Balanced Random Forest).
   - `schedule_revision_risk`    : MODEL PROBABILITY / WARNING SCORE [0.0000, 1.0000] (Regularized Logistic Regression).
   - `selected_integrated_risk`  : OPERATIONAL RISK INDEX [0.0000, 1.0000] (Evidence-weighted composite, NOT a calibrated probability).
   - `execution_stress_index`    : DETERMINISTIC ANALYTICAL INDEX [0.0000, 1.0000] (Point-in-time composite stress, NOT a probability).

3. STRICT PROHIBITION OF UNSUPPORTED ML TARGETS:
   - Supervised Execution Risk ML Target is NOT SUPPORTED (`SUPERVISED_EXECUTION_RISK_TARGET = NOT_SUPPORTED`). Ground-truth bottleneck
     labels do not exist in published PAIMANA reports; candidate stagnation targets suffer severe administrative base-rate collapse.
     The backend must NEVER represent execution stress as a supervised "failure probability".
   - `cost_revision_event_3m` is STRICTLY BANNED from all production tables and endpoints due to Out-of-Time generalization failure.

4. OCMS HISTORICAL DATA POLICY (ANALYTICS CONTEXT ONLY):
   `OCMS_EXPERIMENT_VALIDITY = VALID_AFTER_DOCUMENTATION_CORRECTION`. Adding OCMS historical priors to the 75 PAIMANA features
   consistently degraded Out-of-Time predictive performance. Therefore, OCMS historical data MUST NOT be fed into the production ML
   inference pipeline. It is strictly reserved for historical benchmarking, agency profiles, and decision-support context.

5. BACKEND DECOUPLING (BATCH-FIRST / CACHED SERVING):
   The backend web server (e.g. FastAPI / Node.js) MUST NOT execute synchronous ML model training or dynamic un-cached feature engineering
   in the HTTP request-response cycle. All historical predictions are pre-computed into indexed tables (`ml_risk_scores`, `execution_stress_scores`),
   and new monthly PDF ingestions are processed asynchronously via Celery/Redis background worker pipelines.

6. STRICT TEMPORAL INVARIANCE (ZERO LOOKAHEAD LEAKAGE):
   When computing derived analytics or serving historical snapshots as of month t, the backend MUST NEVER incorporate data from
   months > t. Future facts must never leak into historical views.

PART 1 — THE TWO-PILLAR AI/ML ANALYTICAL ARCHITECTURE
========================================================================================================================

The AI/ML subsystem is structured into two non-overlapping, mathematically distinct pillars:

------------------------------------------------------------------------------------------------------------------------
1.1 PILLAR 1 — PREDICTIVE OUTCOME ENGINE (3-Month Fixed-Horizon ML Forecasting)
------------------------------------------------------------------------------------------------------------------------
Predicts project distress at horizon t + 3 months using data available strictly on or before reporting month t.

1. Primary Outcome: Schedule Delay Risk (`schedule_delay_risk`)
   - Target Definition   : Binary indicator. 1 if project experiences schedule delay (DOC > original DOC) at t + 3 months.
   - Champion Model      : RF_02 (Random Forest: 200 estimators, max_depth=12, min_samples_leaf=5, max_features='sqrt').
   - Calibration Pipeline: Sigmoid / Platt Scaling (fitted strictly on Validation set logits via LogisticRegression).
   - Serialized Artifact : `ml/calibration_final/rf02_calibrated.pkl`.
   - Out-of-Time Metrics : ROC-AUC = 0.9723, PR-AUC = 0.9722, Calibrated Brier Score = 0.0389, ECE = 0.0279.
   - Mathematical Output : Calibrated posterior probability P(Schedule_Delay = 1 | X_t) in range [0.0000, 1.0000].
   - Backend Type        : Float64 [0.0000, 1.0000].

2. Secondary Outcome 1: Cost Overrun Risk (`cost_overrun_risk`)
   - Target Definition   : Binary indicator. 1 if project is in a cost overrun state (revised_cost > original_cost) at t + 3 months.
   - Champion Model      : Balanced Random Forest (200 estimators, max_depth=12, min_samples_leaf=5, class_weight='balanced').
   - Serialized Artifact : `ml/secondary_targets/best_model_rf_cost_overrun_balanced.joblib`.
   - Out-of-Time Metrics : ROC-AUC = 0.9895, PR-AUC = 0.9881, Brier Score = 0.0386, Precision@Top10% = 99.74%, Lift = 3.13x.
   - Mathematical Output : Continuous model risk score / probability in range [0.0000, 1.0000].
   - Backend Type        : Float64 [0.0000, 1.0000].

3. Secondary Outcome 2: Schedule Revision Warning (`schedule_revision_risk`)
   - Target Definition   : Binary indicator. 1 if project experiences a formal administrative completion date revision at t + 3 months.
   - Champion Model      : Regularized Logistic Regression (L2 penalty, unweighted, C=1.0, solver='liblinear'/'lbfgs').
   - Serialized Artifact : `ml/secondary_targets/best_model_logreg_schedule_revision.joblib`.
   - Out-of-Time Metrics : ROC-AUC = 0.8264, PR-AUC = 0.0519, Precision@Top10% = 4.22%, Lift = 3.55x.
   - Mathematical Output : Model probability / continuous early warning score in range [0.0000, 1.0000].
   - Backend Type        : Float64 [0.0000, 1.0000].

4. Integrated Predictive Risk Index (`selected_integrated_risk` / `integrated_risk`)
   - Formulation         : Candidate B (Evidence-Weighted Architecture selected on Validation split).
   - Exact Formula       :
     integrated_risk = (0.50 * schedule_delay_risk) + (0.35 * cost_overrun_risk) + (0.15 * schedule_revision_risk)
   - Nature              : Multi-dimensional operational prioritization index in [0.0000, 1.0000].
   - CRITICAL GUARDRAIL  : MUST NOT be described or serialized as a calibrated univariate probability.
   - Component Weights   :
     * `schedule_contribution`          = 0.50 * schedule_delay_risk          (Range: [0.0000, 0.5000])
     * `cost_contribution`              = 0.35 * cost_overrun_risk            (Range: [0.0000, 0.3500])
     * `schedule_revision_contribution` = 0.15 * schedule_revision_risk       (Range: [0.0000, 0.1500])
     * `schedule_contrib_pct`           = (schedule_contribution / integrated_risk) * 100.0 (if risk > 0 else 0)
     * `cost_contrib_pct`               = (cost_contribution / integrated_risk) * 100.0     (if risk > 0 else 0)
     * `schedule_rev_contrib_pct`       = (schedule_revision_contribution / integrated_risk) * 100.0
   - Dominant Factor     : `dominant_component` = argmax(schedule_contribution, cost_contribution, schedule_revision_contribution)
     Values: 'Schedule Delay' (63.94% portfolio share) | 'Cost Overrun' (35.78%) | 'Schedule Revision' (0.28%).

5. Predictive Risk Band Classification (`risk_band`):
   - Production Triage Tiers (Candidate B Holdout Validated):
     * 'LOW'       : integrated_risk < 0.30       (Empirical delay rate: 0.08%, Cost overrun: 6.13%)
     * 'MODERATE'  : 0.30 <= integrated_risk < 0.60 (Empirical delay rate: 83.73%, Cost overrun: 12.45%)
     * 'HIGH'      : 0.60 <= integrated_risk < 0.80 (Empirical delay rate: 90.58%, Cost overrun: 76.83%)
     * 'VERY_HIGH' : integrated_risk >= 0.80       (Empirical delay rate: 97.73%, Cost overrun: 99.77%)
   - Standardized Operational Tier Mapping (for unified cross-quadrant monitoring with ESI):
     * Standardized Band 1: < 0.35 (Low Priority)
     * Standardized Band 2: 0.35 – < 0.55 (Moderate Priority)
     * Standardized Band 3: 0.55 – < 0.75 (High Priority)
     * Standardized Band 4: >= 0.75 (Very High Priority)
   - Invariant: Monotonicity strictly holds across both boundary conventions.

1.2 PILLAR 2 — OPERATIONAL EXECUTION SURVEILLANCE (Point-in-Time Execution-Stress Index)
------------------------------------------------------------------------------------------------------------------------
Evaluates current observable site friction, physical stagnation, and financial divergence at reporting month t.

1. Scientific Finding: `SUPERVISED_EXECUTION_RISK_TARGET = NOT_SUPPORTED`
   - PAIMANA published reports do not track contractor dispute logs, court stays, or granular milestone tables.
   - Candidate supervised stagnation targets experienced a 2.5x base-rate collapse (37.3% Train -> 16.1% Val) due to
     administrative reporting transitions (Table 1 to Table 6) rather than true site acceleration.
   - Empirical classifiers failed on OOT test data (Logistic Regression ROC-AUC = 0.5585, RF PR-AUC = 0.4739).
   - Therefore, execution surveillance is formulated as a deterministic, leak-free analytical index.

2. Operational Execution-Stress Index (ESI) Formula:
   ESI = (0.30 * S_stag) + (0.25 * S_vel) + (0.20 * S_div) + (0.15 * S_sched) + (0.10 * S_rep)
   - Range: [0.0000, 1.0000].
   - Nature: Deterministic point-in-time composite analytical index.
   - NOT a failure probability, NOT a causal diagnosis, NOT proof of contractor default.

3. The 5 Core ESI Stress Components:
   - S_stag (30% weight): Physical Progress Stagnation Stress
     * Formula: `clip(0.7 * (months_stag / 4.0) + 0.3 * (months_stag / 4.0 * rem_prog_ratio), 0.0, 1.0)`
     * Input Signals: `months_since_last_progress_increase_t`, `remaining_physical_progress_t`.
     * Stress Flag (`flag_stag`): 1 if `months_stag >= 3` OR `stagnant_3m_t == 1`, else 0.
   - S_vel (25% weight): Progress Velocity Deterioration Stress
     * Formula: Piecewise linear: 1.0 if velocity <= 0.0%/mo, 0.75 at 0.5%/mo, 0.40 at 1.5%/mo, 0.0 at >= 3.0%/mo.
     * Input Signals: `progress_velocity_3m_t` (fallback: `progress_velocity_1m_t`).
     * Stress Flag (`flag_vel`): 1 if `velocity < 0.5%/month`, else 0.
   - S_div (20% weight): Expenditure / Physical Progress Divergence Stress
     * Formula: `clip((expenditure_ratio_pct_t - physical_progress_t) / 75.0, 0.0, 1.0)` (0.0 if spread <= 0).
     * Input Signals: `expenditure_ratio_pct_t`, `physical_progress_percent`.
     * Stress Flag (`flag_div`): 1 if `divergence_spread > 25.0% points`, else 0.
   - S_sched (15% weight): Schedule Slippage Magnitude & Overdue Debt Stress
     * Formula: `clip(0.6 * clip(slippage_months / 36.0, 0, 1) + 0.4 * clip(-months_to_orig_doc / 24.0, 0, 1) * is_overdue, 0.0, 1.0)`
     * Input Signals: `schedule_slippage_months_t`, `months_to_original_doc_t`.
     * Stress Flag (`flag_sched`): 1 if `slippage >= 12 months` OR `months_to_orig_doc < -6 months`, else 0.
   - S_rep (10% weight): Observation Quality & Reporting Friction Stress
     * Formula: `clip(0.4 * obs_gap + 0.3 * miss_prog + 0.3 * clip(revisions / 3.0, 0, 1), 0.0, 1.0)`
     * Input Signals: `observation_gap_flag_t`, `missing_physical_progress_t`, `schedule_revision_count_to_date_t`.
     * Stress Flag (`flag_rep`): 1 if `obs_gap == 1` OR `miss_prog == 1` OR `revisions >= 2`, else 0.
   - Total Active Flags (`total_stress_flags`): `flag_stag + flag_vel + flag_sched + flag_div + flag_rep` (Range: 0 to 5).

4. ESI Operational Alert Tiers (`esi_tier` / `execution_stress_band`):
   - 'NOMINAL'       : ESI < 0.35          (~65.2% of project-months; Smooth physical execution, balanced spending)
   - 'WATCH'         : 0.35 <= ESI < 0.55  (~26.9% of project-months; Early deceleration, 1-2 months stagnation)
   - 'ATTENTION'     : 0.55 <= ESI < 0.75  (~7.6% of project-months; Confirmed stagnation >= 3m OR divergence > 25%)
   - 'HIGH_PRIORITY' : ESI >= 0.75         (~0.2% of project-months; Critical deadlock across 3+ dimensions)

5. Dominant Execution Stressor (`dominant_stressor`):
   - Definition: Component contributing the highest weighted share to ESI.
   - Values: 'Progress Velocity Collapse' (56.3% of high-stress alerts) | 'Physical Progress Stagnation' (43.7%) |
             'Expenditure Divergence' | 'Schedule Slippage Debt' | 'Reporting Friction'.

------------------------------------------------------------------------------------------------------------------------
1.3 WHY BOTH PILLARS EXIST: NON-REDUNDANCY & COMPLEMENTARY MONITORING
------------------------------------------------------------------------------------------------------------------------
A rigorous overlap audit proved that Pillar 1 (Predictive Risk) and Pillar 2 (Execution Stress) are non-redundant:
- Rank Correlation: Spearman rho between ESI and Integrated Predictive Risk is only rho = 0.1360 (Pearson r = 0.1590),
  confirming ~66% of execution dynamics are completely uncaptured by predictive models.
- The 65.4% Off-Diagonal Discovery: Exactly 65.4% of high-stress execution alerts (809 project-months) occur on projects
  classified as 'LOW' or 'MODERATE' predictive risk by the ML models!
  * Group A (High ESI >= 0.55, Low/Mod Predictive Risk < 0.55): Early-stage projects with sanctioned deadlines 3 years away.
    Predictive delay models show low near-term breach risk, but the site is currently frozen with 0% progress for 4 months.
    ESI detects the emerging bottleneck years before predictive models trigger.
  * Group B (Low ESI < 0.35, High/Very High Predictive Risk >= 0.55): Mature legacy projects delayed a decade ago. While
    mathematically guaranteed to miss original sanction DOC (High Risk), active construction is advancing smoothly at 3.5%/mo.
    ESI prevents false operational alarms on rehabilitated projects.

PART 5 — DETERMINISTIC LAYER B DERIVED ANALYTICS ENGINE
========================================================================================================================

The backend computes 12 deterministic derived engineering metrics from raw facts (zero ML compute):
1. `cost_escalation_crore`              = revised_cost_crore - original_cost_crore
2. `cost_escalation_percent`            = ((revised_cost - original_cost) / original_cost) * 100.0 (0.0 if orig == 0)
3. `expenditure_ratio_percent`          = (cumulative_expenditure / original_cost) * 100.0
4. `remaining_physical_progress`        = 100.0 - physical_progress_percent
5. `schedule_slippage_months`           = months_between(revised_completion_date, original_completion_date) (0.0 if revised is null)
6. `months_to_original_doc`             = months_between(original_completion_date, report_month) (Negative = past due)
7. `project_age_months`                 = months_between(report_month, approval_start_date)
8. `planned_duration_months`            = months_between(original_completion_date, approval_start_date)
9. `progress_velocity_1m`               = progress(t) - progress(t-1)
10. `progress_velocity_3m`              = (progress(t) - progress(t-3)) / 3.0
11. `stagnant_3m_flag`                  = 1 if (progress(t) - progress(t-3) == 0.0) else 0
12. `expenditure_progress_divergence`   = expenditure_ratio_percent - physical_progress_percent

PART 7 — OCMS HISTORICAL DATA INTEGRATION & GOVERNANCE POLICY

7.1 EMPIRICAL AUDIT VERDICT:
- Formal Finding: `OCMS_EXPERIMENT_VALIDITY = VALID_AFTER_DOCUMENTATION_CORRECTION`.

- AUTHORIZED USE: OCMS historical data is strictly authorized for:
  1. Agency multi-decade historical profiles and benchmarking cards.
  2. Sector-wide historical completion timelines and cost escalation baselines.
  3. Pre-PAIMANA longitudinal trajectory visualization for the 1,442 mapped projects.
  4. Executive decision-support context.
- Schema Separation: Backend must store OCMS data in dedicated benchmark tables (`ocms_historical_benchmarks`)
  completely separate from real-time ML feature ingestion.

PART 8 — ML & ESI SERVING ARCHITECTURE CONTRACT
========================================================================================================================

8.1 INFERENCE SERVING MODES:
- MODE A (Pre-computed Matrices): Ingest `ml/risk_engine/integrated_risk_scores.csv` and
  `experiments/execution_risk/execution_stress_scores.csv` directly into PostgreSQL tables (`ml_risk_scores`, `execution_stress_scores`).
  API queries fetch indexed rows by `(project_id, report_month)` with sub-10ms latency.
- MODE B (Asynchronous Batch Worker for New Monthly Reports):
  When a new Flash Report PDF (e.g. `FlashReport_July_2026.pdf`) is uploaded:
  1. Extract tables via PyMuPDF -> validate and insert into `monthly_snapshots` for `report_month = '2026-07'`.
  2. Generate 75 point-in-time features using data <= 2026-07.
  3. Execute frozen models:
     - `rf02_calibrated.pkl` -> `schedule_delay_risk`
     - `best_model_rf_cost_overrun_balanced.joblib` -> `cost_overrun_risk`
     - `best_model_logreg_schedule_revision.joblib` -> `schedule_revision_risk`
  4. Compute `selected_integrated_risk = 0.50*Sched + 0.35*Cost + 0.15*SRev`, assign `risk_band`, `dominant_component`.
  5. Compute 5 ESI components ($S_{\text{stag}}, S_{\text{vel}}, S_{\text{sched}}, S_{\text{div}}, S_{\text{rep}}$), calculate ESI,
     assign `esi_tier`, `dominant_stressor`, and prescriptive monitoring actions.
  6. Bulk-insert into `ml_risk_scores` and `execution_stress_scores`, trigger alerts, and flush Redis caches.
