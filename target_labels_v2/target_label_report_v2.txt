2. V2 TARGET FORMULATIONS & METHODOLOGICAL PRINCIPLES
----------------------------------------------------
A. PRIMARY TARGET: schedule_delay_3m (Operational Schedule Delay Outcome)
   - Meaning: At prediction month t, does the project breach its sanctioned original completion date
              within or by the 3-month future evaluation horizon (t+3)?
   - Baseline Schedule: original_completion_date (sanctioned baseline schedule; never revised DOC).
   - Positive Class (1): Project is actively ongoing in Table 6 at t+3 and t+3 > original_DOC,
                         OR completed in Table 3 between (t, t+3] with actual_DOC > original_DOC.
   - Negative Class (0): Project is actively ongoing in Table 6 at t+3 and t+3 <= original_DOC,
                         OR completed in Table 3 between (t, t+3] with actual_DOC <= original_DOC.
   - Unlabelled (NaN): Missing original DOC, or project exited before t+3 without Table 3 entry.
   - CRITICAL V2 RULE: Future revised DOC alone is NOT used as proof of operational delay.

B. SEPARATE TARGET: schedule_revision_3m (Administrative Rescheduling Event)
   - Meaning: During (t, t+3], is an official revised completion date greater than the original DOC
              newly observed or sanctioned for this project?
   - Positive Class (1): A revised DOC > original DOC is newly observed in (t, t+3] that was not
                         already known/sanctioned on or before month t.
   - Negative Class (0): Project is observed at t+3 and no new delayed schedule revision occurred.
   - Unlabelled (NaN): Missing baseline original DOC or unresolved project exit.

C. SECONDARY TARGET (STATE): cost_overrun_state_3m (State Outcome)
   - Meaning: At t+3, is the reported cost higher than the original sanctioned cost?
   - Positive Class (1): revised_cost(t+3) > original_cost + 0.01 Cr.
   - Negative Class (0): revised_cost(t+3) <= original_cost + 0.01 Cr.

D. SECONDARY TARGET (EVENT): cost_revision_event_3m (New Escalation Event)
   - Meaning: During (t, t+3], does a NEW upward cost escalation above max(original_cost, revised_cost_t)
              occur and become officially reported?
   - Positive Class (1): revised_cost(t+3) > max(original_cost, revised_cost_t) + 0.01 Cr.
   - Negative Class (0): Project is observed at t+3 and no new upward cost hike occurred.

4. IN-DEPTH ANALYSIS OF UNRESOLVED PROJECT EXITS
------------------------------------------------
Total Unresolved Exit Snapshots: 3,490 (22.14% of candidate snapshots)

Key Empirical Findings from unresolved_exit_analysis.csv:
  1. July-November 2025 Focused-Cohort Impact:
     * 3,321 of 3,490 unresolved exits (95.16%) occurred because the 3-month
       evaluation horizon fell in the July-November 2025 reporting period (when MoSPI Table 6 temporarily
       reported a focused cohort of ~800 major highway/rail infrastructure projects).
  2. Subsequent Longitudinal Reappearance:
     * 1,901 of the unresolved exit snapshots (54.47%) represent projects that REAPPEAR
       in subsequent MoSPI reports (e.g. Dec 2025 - Jun 2026) once Table 6 expanded back to 1,400-1,950 projects.
  3. Genuinely Unresolved Dropouts:
     * Only 161 snapshots (4.61%) represent genuine project dropouts outside the July-Nov window
       with no subsequent reappearance or Table 3 completion record.
  4. Methodological Rule Enforced:
     * ABSENCE FROM TABLE 6 MUST NEVER BE FALSELY IMPUTED AS COMPLETION OR DELAY.
     * These rows are safely and correctly kept as NaN in the target dataset.

7. FINAL RECOMMENDATIONS & READINESS ASSESSMENT
----------------------------------------------
1. Is schedule_delay_3m suitable as the primary ML target?
   YES. It reflects pure operational delivery schedule delay with 11,893 labelled instances
   and balanced ~55% / 45% distribution without mixing administrative paperwork.

2. Is schedule_revision_3m suitable as a secondary target?
   YES. It isolates new administrative rescheduling events (279 positive cases) suitable for early warning.

3. Is cost_overrun_state_3m suitable as a secondary target?
   YES. Highly reliable (12,154 labelled instances, 31.0% positive) tracking budget escalation.

4. Is cost_revision_event_3m reliably constructible?
   YES. Identifies 543 distinct instances where a project's budget was hiked in the future 3-month window.

5. Are unresolved cases acceptable for modelling?
   YES. 95.16% are verified reporting-structure artifacts from July-Nov 2025; retaining NaN prevents
   false label noise and preserves dataset integrity.

6. Are there any remaining leakage risks?
   ZERO. All targets evaluate strictly in [t+1, t+3] while as-of-t baselines are preserved.
