1. EXECUTIVE SUMMARY & CORE LEAKAGE AXIOM
------------------------------------------------------------------------------------------------------------------------
In predictive machine learning for capital project monitoring, the cardinal failure mode is "Temporal Leakage" — using
information from the future relative to the prediction instant $t$ to train models or compute benchmarking statistics.

The SIH26103 Causal Axiom:
For any prediction made at snapshot month $t \in [\text{2025-04}, \text{2026-06}]$:
  1. Current Active Features: MUST use information published strictly at $t_{\text{report}} == t$.
  2. Dynamic Trajectory Features: MUST use historical sequences where $t_{\text{sequence}} \le t$.
  3. Historical Benchmark Features: MUST use completed project evidence where $t_{\text{completion}} < t$.
  4. STRICT PROHIBITION: ZERO information from $t_{\text{future}} > t$ (e.g. future completion status, future cost escalations,
     future physical progress increases, or future schedule revisions) may enter the feature matrix.


========================================================================================================================
2. STATIC VS. DYNAMIC CLUSTERING ARCHITECTURE
========================================================================================================================

A critical methodological question raised in the investigation is:
"Should project clusters be computed statically on pre-transition data, or re-clustered dynamically at every month $t$?"

Evaluation of Approaches:

Approach 1: Dynamic Rolling Re-Clustering at Month t — [REJECTED]
- Mechanism: At each month $t$, re-run K-Means across all active projects using data available up to $t$.
- Fatal Flaws:
  1. Cluster Label Flipping: K-Means cluster IDs are permuted arbitrarily on each run; Cluster 0 at month $t$ may become
     Cluster 3 at month $t+1$, causing severe instability in downstream ML models.
  2. Moving Centroids: Cluster boundaries drift over time, destroying feature interpretability for decision-makers.
  3. Increased Computational Complexity: Re-fitting clustering pipelines across 15 separate prediction months creates
     unnecessary operational overhead without statistical benefit.

Approach 2: Static Pre-Transition Fitting + Point-in-Time Projection — [RECOMMENDED & CERTIFIED]
- Mechanism:
  1. The clustering space is fitted ONCE using pre-transition baseline features and pre-PAIMANA historical trajectory
     records ($t_{\text{evidence}} \le \text{March 2025}$).
  2. The centroid vectors $\boldsymbol{\mu}_0, \boldsymbol{\mu}_1, \boldsymbol{\mu}_2, \boldsymbol{\mu}_3$ and the scaler
     parameters ($\boldsymbol{\mu}_{\text{scaler}}, \boldsymbol{\sigma}_{\text{scaler}}$) are FROZEN permanently.
  3. For any project active at prediction month $t$:
     - Its feature vector $\mathbf{x}_i(t)$ is evaluated using its static baseline properties and historical pre-entry behavior.
     - Its cluster assignment $k^*_i = \arg\min_k \|\mathbf{x}_i - \boldsymbol{\mu}_k\|_2$ and Euclidean distance to centroid
       $d_i = \|\mathbf{x}_i - \boldsymbol{\mu}_{k^*}\|_2$ are evaluated purely deterministically.
- Causal Proof: Because the centroids and scaler are derived entirely from evidence preceding the PAIMANA operational
  horizon ($t_{\text{fit}} \le \text{2025-03} < \text{2025-04}$), the static clustering layer contains ZERO future information.

3. POINT-IN-TIME BENCHMARK CALCULATION RULES
========================================================================================================================

When computing the historical benchmark for Cluster $k$ as of prediction month $t$:

A. Allowed Evidence:
- Historical completed projects in `historical_completed_projects.csv` that satisfy:
  $$\text{actual\_completion\_date} < t$$
- For example:
  * At $t = \text{2025-04}$: All historical projects completed on or before March 2025 ($N = 2,394$).
  * At $t = \text{2026-02}$ (OOT Test): All projects completed on or before January 2026.

B. Prohibited Evidence:
- Projects completed at or after month $t$ ($\text{actual\_completion\_date} \ge t$).
- Current active projects that will complete in the future within the prediction horizon ($H = 3$ months).
- Using the PAIMANA 3-month target labels (`schedule_delay_3m`, `cost_overrun_state_3m`) to calculate historical cluster statistics.


========================================================================================================================
4. INFERENCE PROTOCOL FOR UNMATCHED INCEPTIONS (N = 1,005)
========================================================================================================================

For newly sanctioned projects (sanctioned 2024–2026) that have no pre-PAIMANA OCMS history:
1. Static Subspace Projection:
   - Numerical baseline features (`original_cost_log`, `planned_duration_months`) are fully populated.
   - Historical trajectory features (`pre_paimana_observation_months`, `pre_paimana_schedule_revision_count`,
     `pre_paimana_max_schedule_slippage_months`) are imputed to 0.0 (representing clean initial entry).
2. Projection: The project is assigned to the nearest archetype in the normalized space. (Typically Archetype 1: Standard Road
   or Archetype 0: Mega Project based on budget and duration).
3. Indicator Feature: A binary flag `is_legacy_linked = 0` is passed to the ML model, allowing tree-based estimators to
   distinguish newly initiated projects from legacy projects with zero historical delay.


========================================================================================================================
5. POINT-IN-TIME LEAKAGE AUDIT VERIFICATION PROTOCOL
========================================================================================================================

To guarantee 100% compliance during model training and evaluation:
1. Monotonic Temporal Boundary:
   For all candidate benchmark features $f_j$ joined to snapshot $(i, t)$:
   $$\max \left( \text{Source Evidence Timestamps}(f_j) \right) < t$$
2. Non-Contamination of Temporal Splits:
   - Training Set: Snapshots from April 2025 to November 2025.
   - Validation Set: Snapshots from December 2025 to January 2026.
   - OOT Test Set: Snapshots from February 2026 to March 2026.
   - Cluster definitions and scaler statistics are fitted ONLY on pre-PAIMANA historical records, ensuring zero data leakage
     from Validation or OOT Test periods into the training pipeline.
3. Production Invariance:
   - Production datasets (`data/`, `features/feature_dataset_v1.csv`, `ml/models/`) remain 100% untouched and hashed.
