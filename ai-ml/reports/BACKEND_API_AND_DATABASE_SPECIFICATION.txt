PURPOSE OF THIS SPECIFICATION:
This document defines the production-ready technical architecture, relational database schema (PostgreSQL 16),
derived analytics engine (Layer B calculations), comprehensive RESTful API endpoints, request/response JSON schemas,
indexing strategies, caching policies, background ingestion tasks, and security controls required to implement the
backend service for SIH26103 (MoSPI/IPMD Integrated Project-Monitoring Platform).

SYSTEM ARCHITECTURE SUMMARY:
- Application Framework : FastAPI (Python 3.11+) / Node.js (Express / Fastify) with asynchronous I/O.
- Primary Database      : PostgreSQL 16 with B-Tree composite indexes and JSONB metadata storage.
- In-Memory Cache       : Redis 7 for sub-10ms portfolio aggregations and session/rate-limiting state.
- Task Queue / Worker   : Celery / Redis (or APScheduler) for asynchronous PDF ingestion, feature extraction, and ML scoring.
- ML Inference Bridge   : Local joblib/scikit-learn runtime inside isolated batch worker containers.
- Analytical Pillars    : Clean separation between Pillar 1 (Predictive Outcome Engine) and Pillar 2 (Operational Execution Surveillance).


========================================================================================================================
PART 1 — RELATIONAL DATABASE SCHEMA & POSTGRESQL DDL SPECIFICATION
========================================================================================================================

The database architecture employs a normalized relational structure separating permanent project identities, monthly
longitudinal reporting snapshots, completed/intake tables, pre-computed predictive ML risk scores, operational execution-stress
index (ESI) scores, OCMS historical benchmarking context, and data quality anomaly logs.

```sql
-- ============================================================================
-- 1. EXTENSIONS & ENUM TYPES
-- ============================================================================
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pg_trgm"; -- For fast full-text / trigram fuzzy search

-- Predictive Risk Enums (Pillar 1)
CREATE TYPE risk_band_enum AS ENUM ('LOW', 'MODERATE', 'HIGH', 'VERY_HIGH');
CREATE TYPE dominant_component_enum AS ENUM ('Schedule Delay', 'Cost Overrun', 'Schedule Revision');

-- Operational Execution Surveillance Enums (Pillar 2)
CREATE TYPE esi_tier_enum AS ENUM ('NOMINAL', 'WATCH', 'ATTENTION', 'HIGH_PRIORITY');
CREATE TYPE dominant_stressor_enum AS ENUM (
    'Progress Velocity Collapse',
    'Physical Progress Stagnation',
    'Expenditure Divergence',
    'Schedule Slippage Debt',
    'Reporting Friction'
);
CREATE TYPE prescriptive_action_enum AS ENUM (
    'SITE_OBSTACLE_AUDIT',
    'FINANCIAL_PHYSICAL_ALIGNMENT_AUDIT',
    'RESOURCE_MOBILIZATION_DIRECTIVE',
    'CRITICAL_PATH_RECALIBRATION',
    'DATA_COMPLIANCE_DIRECTIVE',
    'INTER_MINISTERIAL_COMMITTEE_ESCALATION'
);

-- System & Governance Enums
CREATE TYPE alert_severity_enum AS ENUM ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL');
CREATE TYPE alert_source_enum AS ENUM ('PREDICTIVE_ML', 'EXECUTION_SURVEILLANCE', 'RULE_ENGINE');
CREATE TYPE alert_status_enum AS ENUM ('ACTIVE', 'ACKNOWLEDGED', 'RESOLVED');
CREATE TYPE user_role_enum AS ENUM ('MOSPI_ADMIN', 'NODAL_OFFICER', 'PUBLIC_VIEWER');

-- ============================================================================
-- 2. CANONICAL PROJECTS MASTER TABLE
-- ============================================================================
-- Holds immutable or slowly-changing project identity attributes across all reporting months.
CREATE TABLE projects (
    project_id VARCHAR(32) PRIMARY KEY,              -- Canonical 6-digit PAIMANA ID (e.g. '105236', '612786')
    project_name TEXT NOT NULL,                      -- Official full infrastructure project title
    agency VARCHAR(64) NOT NULL,                     -- Implementing CPSU / Agency (e.g. 'NHAI', 'MoRTH', 'NTPC')
    state VARCHAR(128) NOT NULL,                     -- State, UT, or Multi-State location
    legacy_ocms_code VARCHAR(32),                    -- Cross-referenced 8-character OCMS code (e.g. 'N24001476')
    approval_start_date VARCHAR(7) NOT NULL,         -- Sanction approval date in ISO YYYY-MM (e.g. '2021-09')
    original_completion_date VARCHAR(7) NOT NULL,    -- Sanctioned original DOC in ISO YYYY-MM (e.g. '2022-09')
    original_cost_crore NUMERIC(14, 2) NOT NULL,     -- Sanctioned capital budget in ₹ Crore
    is_active BOOLEAN NOT NULL DEFAULT TRUE,         -- Active ongoing status flag
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_projects_agency ON projects (agency);
CREATE INDEX idx_projects_state ON projects (state);
CREATE INDEX idx_projects_legacy_code ON projects (legacy_ocms_code) WHERE legacy_ocms_code IS NOT NULL;
CREATE INDEX idx_projects_name_trgm ON projects USING gin (project_name gin_trgm_ops);

-- ============================================================================
-- 3. MONTHLY LONGITUDINAL SNAPSHOTS TABLE (LAYER A RAW FACTS)
-- ============================================================================
-- Stores monthly time-series records (21,555 rows). One row per project per report_month.
CREATE TABLE monthly_snapshots (
    snapshot_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    project_id VARCHAR(32) NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    report_month VARCHAR(7) NOT NULL,                -- Snapshot epoch in ISO YYYY-MM (e.g. '2025-04')
    revised_completion_date VARCHAR(7),              -- Current anticipated DOC in YYYY-MM (Null if unrevised)
    revised_cost_crore NUMERIC(14, 2) NOT NULL,      -- Current anticipated cost in ₹ Crore
    cumulative_expenditure_crore NUMERIC(14, 2) NOT NULL, -- Total expenditure to date in ₹ Crore
    physical_progress_percent NUMERIC(5, 2) NOT NULL,-- Cumulative physical completion percentage [0.00, 100.00]
    source_file VARCHAR(128) NOT NULL,               -- Source Flash Report PDF filename
    source_table VARCHAR(64) NOT NULL,               -- e.g. 'Table 6: All Ongoing Projects'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    
    CONSTRAINT uq_project_month UNIQUE (project_id, report_month),
    CONSTRAINT chk_progress_bounds CHECK (physical_progress_percent >= 0.0 AND physical_progress_percent <= 100.0),
    CONSTRAINT chk_costs_positive CHECK (revised_cost_crore >= 0.0 AND cumulative_expenditure_crore >= 0.0)
);

CREATE INDEX idx_snapshots_report_month ON monthly_snapshots (report_month);
CREATE INDEX idx_snapshots_project_month ON monthly_snapshots (project_id, report_month);

-- ============================================================================
-- 4. MACHINE LEARNING RISK SCORES TABLE (PILLAR 1: PREDICTIVE OUTCOME ENGINE)
-- ============================================================================
-- Stores multi-dimensional predictive outcome scores (15,769 pre-computed rows across 12 epochs).
CREATE TABLE ml_risk_scores (
    score_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    project_id VARCHAR(32) NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    report_month VARCHAR(7) NOT NULL,                -- Prediction snapshot epoch (YYYY-MM)
    schedule_delay_risk NUMERIC(6, 4) NOT NULL,      -- Platt-calibrated probability in [0.0000, 1.0000]
    cost_overrun_risk NUMERIC(6, 4) NOT NULL,        -- Continuous model score in [0.0000, 1.0000]
    schedule_revision_risk NUMERIC(6, 4) NOT NULL,   -- Model probability / warning score in [0.0000, 1.0000]
    selected_integrated_risk NUMERIC(6, 4) NOT NULL, -- Weighted multi-dimensional operational index [0.0000, 1.0000]
    risk_band risk_band_enum NOT NULL,               -- 'LOW', 'MODERATE', 'HIGH', 'VERY_HIGH'
    dominant_component dominant_component_enum NOT NULL, -- 'Schedule Delay', 'Cost Overrun', 'Schedule Revision'
    schedule_contribution NUMERIC(6, 4) NOT NULL,    -- 0.50 * schedule_delay_risk
    cost_contribution NUMERIC(6, 4) NOT NULL,        -- 0.35 * cost_overrun_risk
    schedule_revision_contribution NUMERIC(6, 4) NOT NULL, -- 0.15 * schedule_revision_risk
    model_version VARCHAR(32) NOT NULL DEFAULT 'v1.0.0-rf02-calibrated',
    feature_version VARCHAR(32) NOT NULL DEFAULT 'v1.0.0-75features-pit',
    scored_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    CONSTRAINT uq_ml_project_month UNIQUE (project_id, report_month)
);

CREATE INDEX idx_ml_scores_month_band ON ml_risk_scores (report_month, risk_band);
CREATE INDEX idx_ml_scores_integrated ON ml_risk_scores (report_month, selected_integrated_risk DESC);
CREATE INDEX idx_ml_scores_dominant ON ml_risk_scores (report_month, dominant_component);

-- ============================================================================
-- 5. OPERATIONAL EXECUTION STRESS TABLE (PILLAR 2: EXECUTION SURVEILLANCE)
-- ============================================================================
-- Stores deterministic point-in-time execution stress index scores (15,769 pre-computed rows).
-- Formula: ESI = 0.30 * S_stag + 0.25 * S_vel + 0.20 * S_div + 0.15 * S_sched + 0.10 * S_rep
CREATE TABLE execution_stress_scores (
    esi_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    project_id VARCHAR(32) NOT NULL REFERENCES projects(project_id) ON DELETE CASCADE,
    report_month VARCHAR(7) NOT NULL,                -- Evaluation snapshot epoch (YYYY-MM)
    s_stag NUMERIC(6, 4) NOT NULL,                   -- Physical progress stagnation stress [0.0000, 1.0000]
    s_vel NUMERIC(6, 4) NOT NULL,                    -- Progress velocity deterioration stress [0.0000, 1.0000]
    s_div NUMERIC(6, 4) NOT NULL,                    -- Expenditure/progress divergence stress [0.0000, 1.0000]
    s_sched NUMERIC(6, 4) NOT NULL,                  -- Schedule slippage & overdue debt stress [0.0000, 1.0000]
    s_rep NUMERIC(6, 4) NOT NULL,                    -- Observation quality & revision friction [0.0000, 1.0000]
    flag_stag SMALLINT NOT NULL DEFAULT 0,           -- 1 if stagnation active
    flag_vel SMALLINT NOT NULL DEFAULT 0,            -- 1 if severe velocity slowdown
    flag_div SMALLINT NOT NULL DEFAULT 0,            -- 1 if capital divergence > 25%
    flag_sched SMALLINT NOT NULL DEFAULT 0,          -- 1 if slippage >= 12m or overdue > 6m
    flag_rep SMALLINT NOT NULL DEFAULT 0,            -- 1 if reporting gap / revision count >= 2
    total_stress_flags SMALLINT NOT NULL DEFAULT 0,  -- Sum of active flags (0 to 5)
    execution_stress_index NUMERIC(6, 4) NOT NULL,   -- Deterministic ESI score [0.0000, 1.0000]
    esi_tier esi_tier_enum NOT NULL,                 -- 'NOMINAL', 'WATCH', 'ATTENTION', 'HIGH_PRIORITY'
    dominant_stressor dominant_stressor_enum NOT NULL, -- Dominant observable site friction factor
    suggested_action prescriptive_action_enum NOT NULL, -- Automated prescriptive administrative action
    execution_index_version VARCHAR(32) NOT NULL DEFAULT 'v1.0.0-esi-5dim',
    evaluated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    CONSTRAINT uq_esi_project_month UNIQUE (project_id, report_month)
);

CREATE INDEX idx_esi_scores_month_tier ON execution_stress_scores (report_month, esi_tier);
CREATE INDEX idx_esi_scores_index ON execution_stress_scores (report_month, execution_stress_index DESC);
CREATE INDEX idx_esi_scores_dominant ON execution_stress_scores (report_month, dominant_stressor);
```

PART 2 — DETERMINISTIC LAYER B DERIVED ANALYTICS ENGINE (SQL VIEWS & ENGINE)
========================================================================================================================

The backend computes Layer B derived analytics and joins both Pillar 1 (Predictive ML Risk) and Pillar 2 (Execution Stress Index)
using the optimized PostgreSQL view `v_project_monthly_dossier`.

```sql
CREATE OR REPLACE VIEW v_project_monthly_dossier AS
WITH ranked_snapshots AS (
    SELECT 
        s.snapshot_id,
        s.project_id,
        s.report_month,
        s.revised_completion_date,
        s.revised_cost_crore,
        s.cumulative_expenditure_crore,
        s.physical_progress_percent,
        s.source_file,
        s.source_table,
        p.project_name,
        p.agency,
        p.state,
        p.legacy_ocms_code,
        p.approval_start_date,
        p.original_completion_date,
        p.original_cost_crore,
        
        -- Window lag functions strictly bounded to <= report_month
        LAG(s.physical_progress_percent, 1) OVER (
            PARTITION BY s.project_id ORDER BY s.report_month ASC
        ) AS prev_prog_1m,
        LAG(s.physical_progress_percent, 3) OVER (
            PARTITION BY s.project_id ORDER BY s.report_month ASC
        ) AS prev_prog_3m,
        LAG(s.cumulative_expenditure_crore, 1) OVER (
            PARTITION BY s.project_id ORDER BY s.report_month ASC
        ) AS prev_exp_1m
    FROM monthly_snapshots s
    JOIN projects p ON s.project_id = p.project_id
)
SELECT 
    r.*,
    
    -- LAYER B: DETERMINISTIC DERIVED METRICS
    -- 1. Cost Escalation in ₹ Cr
    (r.revised_cost_crore - r.original_cost_crore) AS cost_escalation_crore,
    
    -- 2. Cost Escalation in %
    CASE 
        WHEN r.original_cost_crore > 0 
        THEN ROUND(((r.revised_cost_crore - r.original_cost_crore) / r.original_cost_crore * 100.0), 2)
        ELSE 0.0 
    END AS cost_escalation_percent,
    
    -- 3. Expenditure Ratio %
    CASE 
        WHEN r.original_cost_crore > 0 
        THEN ROUND((r.cumulative_expenditure_crore / r.original_cost_crore * 100.0), 2)
        ELSE 0.0 
    END AS expenditure_ratio_percent,
    
    -- 4. Remaining Physical Progress %
    (100.0 - r.physical_progress_percent) AS remaining_physical_progress,
    
    -- 5. Schedule Slippage in Months
    CASE 
        WHEN r.revised_completion_date IS NOT NULL 
        THEN (
            (CAST(SUBSTRING(r.revised_completion_date, 1, 4) AS INT) - CAST(SUBSTRING(r.original_completion_date, 1, 4) AS INT)) * 12 +
            (CAST(SUBSTRING(r.revised_completion_date, 6, 2) AS INT) - CAST(SUBSTRING(r.original_completion_date, 6, 2) AS INT))
        )
        ELSE 0.0 
    END AS schedule_slippage_months,
    
    -- 6. Months Remaining to Original Sanctioned Deadline (Negative = Past Due)
    (
        (CAST(SUBSTRING(r.original_completion_date, 1, 4) AS INT) - CAST(SUBSTRING(r.report_month, 1, 4) AS INT)) * 12 +
        (CAST(SUBSTRING(r.original_completion_date, 6, 2) AS INT) - CAST(SUBSTRING(r.report_month, 6, 2) AS INT))
    ) AS months_to_original_doc,
    
    -- 7. 1-Month Progress Velocity (% delta)
    CASE 
        WHEN r.prev_prog_1m IS NOT NULL THEN (r.physical_progress_percent - r.prev_prog_1m)
        ELSE NULL 
    END AS progress_velocity_1m,
    
    -- 8. 3-Month Rolling Average Progress Velocity (% / month)
    CASE 
        WHEN r.prev_prog_3m IS NOT NULL THEN ROUND(((r.physical_progress_percent - r.prev_prog_3m) / 3.0), 2)
        ELSE NULL 
    END AS progress_velocity_3m,
    
    -- 9. 3-Month Stagnation Indicator Flag (1 = Stagnant)
    CASE 
        WHEN r.prev_prog_3m IS NOT NULL AND (r.physical_progress_percent - r.prev_prog_3m = 0.0) THEN 1
        ELSE 0 
    END AS stagnant_3m_flag,
    
    -- 10. Capital Burn vs Physical Progress Divergence (%)
    CASE 
        WHEN r.original_cost_crore > 0 
        THEN ROUND(((r.cumulative_expenditure_crore / r.original_cost_crore * 100.0) - r.physical_progress_percent), 2)
        ELSE 0.0 
    END AS expenditure_progress_divergence,

    -- PILLAR 1: MACHINE LEARNING PREDICTIVE RISK SIGNALS (ml_risk_scores)
    m.schedule_delay_risk,
    m.cost_overrun_risk,
    m.schedule_revision_risk,
    m.selected_integrated_risk,
    m.risk_band,
    m.dominant_component,
    m.schedule_contribution,
    m.cost_contribution,
    m.schedule_revision_contribution,
    CASE 
        WHEN m.selected_integrated_risk > 0 
        THEN ROUND((m.schedule_contribution / m.selected_integrated_risk * 100.0), 2)
        ELSE 0.0 
    END AS schedule_contrib_pct,
    CASE 
        WHEN m.selected_integrated_risk > 0 
        THEN ROUND((m.cost_contribution / m.selected_integrated_risk * 100.0), 2)
        ELSE 0.0 
    END AS cost_contrib_pct,
    CASE 
        WHEN m.selected_integrated_risk > 0 
        THEN ROUND((m.schedule_revision_contribution / m.selected_integrated_risk * 100.0), 2)
        ELSE 0.0 
    END AS schedule_rev_contrib_pct,
    m.model_version,
    m.feature_version,

    -- PILLAR 2: OPERATIONAL EXECUTION SURVEILLANCE SIGNALS (execution_stress_scores)
    e.execution_stress_index,
    e.esi_tier,
    e.dominant_stressor,
    e.suggested_action,
    e.s_stag,
    e.s_vel,
    e.s_div,
    e.s_sched,
    e.s_rep,
    e.flag_stag,
    e.flag_vel,
    e.flag_div,
    e.flag_sched,
    e.flag_rep,
    e.total_stress_flags,
    e.execution_index_version

FROM ranked_snapshots r
LEFT JOIN ml_risk_scores m ON r.project_id = m.project_id AND r.report_month = m.report_month
LEFT JOIN execution_stress_scores e ON r.project_id = e.project_id AND r.report_month = e.report_month;
```

PART 4 — CACHING ARCHITECTURE & QUERY OPTIMIZATION (REDIS 7)
========================================================================================================================

To meet sub-50ms web response latency SLAs, the backend employs a layered Redis caching architecture:

4.1 REDIS KEY TAXONOMY:
- Portfolio KPIs     : `mospi:portfolio:summary:{report_month}` (TTL: 24 hours).
- Agency Breakdown   : `mospi:portfolio:agency:{report_month}` (TTL: 24 hours).
- State Breakdown    : `mospi:portfolio:state:{report_month}` (TTL: 24 hours).
- Project Dossier    : `mospi:project:dossier:{project_id}:{report_month}` (TTL: 12 hours).
- Project Trajectory : `mospi:project:trajectory:{project_id}` (TTL: 24 hours).
- Meta Epochs List   : `mospi:meta:epochs` (TTL: 7 days).

4.2 CACHE INVALIDATION:
When a new monthly report is ingested or an alert acknowledged:
- Flush keys matching pattern `mospi:portfolio:*` and `mospi:meta:*`.
- Selectively invalidate updated project dossiers.

PART 5 — ASYNCHRONOUS WORKER & INGESTION PIPELINE (CELERY / REDIS)
========================================================================================================================

The asynchronous pipeline (`tasks/ingestion_tasks.py`) executes end-to-end processing when a new Flash Report PDF is received:

```python
# tasks/ingestion_tasks.py (Architectural Blueprint)

from celery import Celery
import joblib
import numpy as np
import pandas as pd
from scripts.extract_pdfs import extract_tables_from_pdf
from scripts.normalize_data import normalize_raw_records
from features.build_features_v1 import compute_point_in_time_features
from scripts.execution_risk.esi_calculator import compute_point_in_time_esi

celery_app = Celery("mospi_tasks", broker="redis://localhost:6379/1")

@celery_app.task(bind=True, name="tasks.ingest_flash_report_pdf")
def ingest_flash_report_pdf(self, pdf_file_path: str, report_month: str):
    """
    Executes end-to-end PDF parsing, database insertion, 75-feature calculation,
    batch predictive ML inference, and deterministic ESI scoring for a new report.
    """
    # Step 1: Extract tables using PyMuPDF
    raw_tables = extract_tables_from_pdf(pdf_file_path)
    
    # Step 2: Normalize and validate records
    cleaned_records = normalize_raw_records(raw_tables, report_month)
    
    # Step 3: Insert into monthly_snapshots in PostgreSQL (Transaction)
    db_insert_monthly_snapshots(cleaned_records, report_month)
    
    # Step 4: Compute 75 Point-in-Time features strictly using data <= report_month
    features_df = compute_point_in_time_features(as_of_month=report_month)
    
    # Step 5: Load serialized production ML models (Pillar 1)
    rf_schedule = joblib.load("ml/calibration_final/rf02_calibrated.pkl")
    rf_cost = joblib.load("ml/secondary_targets/best_model_rf_cost_overrun_balanced.joblib")
    lr_srev = joblib.load("ml/secondary_targets/best_model_logreg_schedule_revision.joblib")
    
    # Step 6: Generate predictive risk scores
    sched_risk = rf_schedule.predict_proba(features_df)[:, 1]
    cost_risk = rf_cost.predict_proba(features_df)[:, 1]
    srev_risk = lr_srev.predict_proba(features_df)[:, 1]
    
    # Step 7: Candidate B Integrated Risk synthesis
    integrated_risk = (0.50 * sched_risk) + (0.35 * cost_risk) + (0.15 * srev_risk)
    
    # Step 8: Compute Pillar 2 Operational Execution-Stress Index (ESI)
    esi_results = compute_point_in_time_esi(features_df, report_month)
    
    # Step 9: Bulk insert into ml_risk_scores and execution_stress_scores
    db_bulk_insert_ml_risk_scores(features_df["project_id"], report_month, sched_risk, cost_risk, srev_risk, integrated_risk)
    db_bulk_insert_execution_stress_scores(features_df["project_id"], report_month, esi_results)
    
    # Step 10: Trigger predictive, execution & rule-based alerts
    evaluate_and_insert_alerts(report_month)
    
    # Step 11: Invalidate Redis portfolio caches
    redis_client.flush_matching_keys("mospi:portfolio:*")
    
    return {"status": "SUCCESS", "report_month": report_month, "scored_count": len(features_df)}
```

PART 6 — SECURITY, AUTHENTICATION & ROLE-BASED ACCESS CONTROL (RBAC)
========================================================================================================================

The platform enforces Role-Based Access Control using JWT Bearer tokens:

------------------------------------------------------------------------------------------------------------------------
USER ROLE         PERMISSIONS & ACCESS SCOPE
------------------------------------------------------------------------------------------------------------------------
`PUBLIC_VIEWER`   - Read-only access to portfolio KPIs, project roster, project dossiers, trajectories, and ESI.
                  - Cannot view internal data anomaly logs or trigger report ingestions.
                  - Subject to public rate-limiting (100 requests / minute).

`NODAL_OFFICER`   - Read access to all public data + agency-specific operational drilldowns.
                  - Can acknowledge alerts for projects belonging to their designated agency.
                  - Rate limit: 500 requests / minute.

`MOSPI_ADMIN`     - Full unrestricted system access.
                  - Can upload Flash Report PDFs (`POST /api/v1/ingest/flash-report`).
                  - Can inspect data anomaly logs (`data_anomalies_log`), manage users, and re-run batch scoring.
                  - Rate limit: Unlimited.
