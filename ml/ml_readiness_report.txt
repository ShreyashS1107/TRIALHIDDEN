2. RATIONALE FOR TEMPORAL SPLITTING
-----------------------------------
Infrastructure project monitoring is intrinsically longitudinal. In production deployment, a predictive model
trained on historical monitoring data up to month T must forecast future risk for ongoing projects in future
unseen epochs T+1, T+2, etc. Standard random k-fold cross-validation or shuffled train-test splits cause massive
data leakage by placing future snapshots of project P in the training set and past snapshots of project P in the test
set. The chronological split (Train: Apr-Nov 2025 -> Val: Dec 2025-Jan 2026 -> Test: Feb-Mar 2026) faithfully simulates
real-world production forecasting conditions without lookahead bias.

Longitudinal Integrity Note:
Project overlap across chronological splits is the EXPECTED and INTENDED structure of longitudinal monitoring.
A project observed in Train (e.g. at month t=2025-05) that continues to be monitored in Validation (t=2025-12)
is not a leakage risk because the Validation snapshot's features only use historical records <= 2025-12.
The model in production will always evaluate currently active projects that have past historical observations.
