4. COMPARISON OF SCHEDULE-DELAY TARGET DEFINITIONS
--------------------------------------------------
Definition A: Actual Completion Date > Original Completion Date
  - Measurement: Ground-truth final project delivery schedule overrun.
  - Data Availability: Available ONLY for 350 completed projects in Table 3. NOT available for 2,741 ongoing projects.
  - Suitability: Insufficient sample size (350 projects total) for training generalized ML models.
  - Recommendation: Use for ex-post validation cohort, but not sole training label.

Definition B: Revised Completion Date > Original Completion Date
  - Measurement: Intermediate administrative decision / official rescheduling.
  - Data Availability: Available in 1,809 projects (or dynamically when revised schedule is sanctioned).
  - Leakage Risk: HIGH if used as a contemporaneous feature; SAFE if treated as a future target Y(t+H).
  - Suitability: Moderately suitable as an administrative risk target, but misses unrescheduled delays.

Definition C: Project Breaches Original DOC or Remains Incomplete Beyond Original DOC (Point-in-Time Milestone Delay)
  - Measurement: Operational delay reality. At time t+H, is actual_progress < 100% while current_date > original_DOC?
  - Data Availability: Fully constructible across all 21,555 project-month records for any fixed evaluation horizon H.
  - Leakage Risk: Zero if evaluated strictly at forward horizon (t + H).
  - Recommendation: RECOMMENDED PRIMARY TARGET for operational monitoring platform.

6. COMPARISON OF COST-OVERRUN TARGET DEFINITIONS
-----------------------------------------------
Definition A: Revised Cost > Original Cost (Contemporaneous Snapshot)
  - Measures currently approved cost increase. Creates leakage if used at time t to predict time t status.

Definition B: Future Cost Escalation at Horizon H (Revised_Cost(t+H) > Original_Cost)
  - Measures whether project budget will escalate within forward window H (e.g. 3 or 6 months ahead).
  - Highly defensible, actionable for ministry early-warning intervention.
  - RECOMMENDED SECONDARY TARGET.

7. PREDICTION TIMELINE & POINT-IN-TIME GOVERNANCE
------------------------------------------------
- Monitoring Window: 15 monthly epochs (2025-04 to 2026-06).
- Point-in-Time Principle: At each report month t, features X(t) must strictly incorporate information available at or before month t.
- Usable Prediction Epochs for Horizon H=3 months: 2025-04 through 2026-03 (12 training/validation slices).
- Usable Prediction Epochs for Horizon H=6 months: 2025-04 through 2025-12 (9 training/validation slices).
- Late-Entry Projects: Can enter the prediction pool starting from their intake month (e.g., Table 4 projects).
- Disappearing Projects: Projects exiting before evaluation horizon must be checked against Table 3 (Completed) to resolve true completion vs reporting hiatus.

10. PROJECT-LEVEL VS SNAPSHOT-LEVEL TARGET RECOMMENDATION
---------------------------------------------------------
Concept: SNAPSHOT-LEVEL POINT-IN-TIME PREDICTION (Project i at Reporting Month t)
Justification:
  1. Operational Fidelity: A real-world MoSPI monitoring portal runs monthly risk assessments at each reporting epoch.
  2. Temporal Dynamic Signals: Trajectory velocity (progress rate over last 3 months, expenditure acceleration) changes monthly and provides predictive power.
  3. Longitudinal Sample Size: Yields ~18,000+ valid point-in-time prediction instances across 15 months, compared to only 2,741 static project rows.
  4. Avoids Lookahead Bias: Evaluates model performance using temporal rolling-window validation.
